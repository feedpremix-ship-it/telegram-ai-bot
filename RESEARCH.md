# Модели, бесплатные лимиты и предел нагрузки

Дата проверки: 4 ноября 2026 года. Все прямые запросы к перечисленным ниже официальным сайтам из среды разработки завершились `Tunnel connection failed: 403 Forbidden`. Это ограничение исходящего прокси этой среды, не доказательство недоступности самих сервисов.

Поэтому текущие цены, квоты, отсутствие обязательной карты и доступность отдельных моделей **не подтверждены**. Исторические бесплатные значения не выдаются за актуальные. Никакой платный сервис не включался. Реального Groq-ключа для проверки аккаунта в среде не было.

## Что проверять у Groq

Официальные страницы:

- https://console.groq.com/docs/models
- https://console.groq.com/docs/rate-limits
- https://console.groq.com/docs/tool-use
- Панель **Limits** именно вашей организации Groq.

| Кандидат | Предполагаемая роль (нужно проверить на ваших задачах) | Подтверждённые в этой задаче данные |
|---|---|---|
| `openai/gpt-oss-120b` | Основной кандидат для сложного анализа и русского текста | Актуальная доступность, окно контекста, скорость, RPM/RPD/TPM/TPD и бесплатность не проверены |
| `openai/gpt-oss-20b` | Более компактный резервный кандидат | Те же ограничения проверки; сравнительный русский benchmark не проводился |
| Другие модели из `/openai/v1/models` | Возможная замена через `GROQ_MODELS` | Нет разрешённого тестового ключа и возможности проверить tool calling |

Больший размер модели сам по себе не гарантирует лучшее качество русского ответа или меньшую задержку. В этом проекте нет доказанного сравнительного бенчмарка. Старт приложения проверяет присутствие выбранных идентификаторов в `/models`, но эта проверка не доказывает квоту, качество, поддержку инструментов и успешный чат. Для этого нужен один реальный диалог и отдельные запросы погоды/графика.

API использует `max_completion_tokens`, `tools`, `tool_choice=auto`, `parallel_tool_calls=false`; `temperature`, специфические параметры скрытого reasoning и непроверенные structured-output режимы не добавлены. Совместимость проверена заглушками формы API, не действующим Groq. При несовместимости параметров бот выдаёт безопасную ошибку вместо многократного переключения моделей и расхода квоты.

Модельный контекст не переполняется без ограничения: приложение передаёт до 12000 символов истории, до 6000 символов текущего запроса и до 12000 символов результата одного инструмента плюс системный текст. Это локальные пределы, а не заявление о размере контекста модели. Фактическое окно из текущей документации проверьте до production.

Устаревший `deepseek-r1-distill-llama-70b` удалён из значений по умолчанию. `llama-3.3-70b-versatile` не объявляется устаревшей без текущих данных; из default-цепочки она исключена ради единой проверяемой конфигурации инструментов. Старое значение `GROQ_MODELS` в Render нужно обновить вручную, иначе Environment продолжит переопределять default.

## Расчёт 5000–6000 пользовательских запросов в сутки

6000 / 1440 ≈ **4,17 пользовательского запроса в минуту в среднем**, но реальные всплески значительно выше среднего. Пусть `c` — среднее число LLM-вызовов на запрос (1 для обычного ответа, обычно 2 для инструментов), `t` — среднее число входных и выходных токенов одного LLM-вызова:

`N ≤ min(RPD/c, TPD/(c*t), 1440*RPM/c, 1440*TPM/(c*t))`.

Если лимиты общие для организации, их нельзя складывать по моделям или API-ключам. Распределение запросов между моделями также не даёт права обходить общую квоту.

Иллюстрация, **не текущая квота Groq**: при `RPD=1000`, `TPD=200000` и `t=1500` предел по токенам — около 133 простых запросов в сутки, ещё меньше для инструментов. Для 6000 простых запросов по 1500 токенов нужно около **9 миллионов токенов/сутки**. Если каждый запрос делает два таких вызова — около 18 миллионов. История диалога увеличивает входной расход. Ограничение длины только ответов этого не решает.

В поставленной конфигурации `DAILY_REQUEST_LIMIT=900`, поэтому **6000 запросов заведомо не поддерживаются этой конфигурацией**; консервативный токенный резерв сокращает предел ещё сильнее. Предельное число запросов действующего бесплатного аккаунта не удалось установить, поэтому цель 5000–6000 за 0 рублей здесь **не подтверждена**, а не обещана и не объявлена математически невозможной для любых сервисов.

Без подтверждения тарифов других провайдеров дополнительные LLM-провайдеры не подключались. Ротация множества ключей/аккаунтов, платные fallback API и автоматическое создание подписок отсутствуют.

## PostgreSQL: Neon и Supabase

Официальные страницы для проверки перед созданием:

- https://neon.com/pricing
- https://neon.com/docs/connect/connect-from-any-app
- https://supabase.com/pricing
- https://supabase.com/docs/guides/database/connecting-to-postgres

| Критерий | Neon | Supabase |
|---|---|---|
| Совместимость приложения | Стандартный PostgreSQL, нужен прямой endpoint с TLS | Стандартный PostgreSQL, нужен прямой endpoint с TLS |
| Бесплатное хранилище/compute/egress | Текущие числа не подтверждены: проверьте Free в панели | Текущие числа не подтверждены: проверьте Free в панели |
| Обязательная карта/платный upgrade | Не подтверждено: не соглашайтесь на платный план | Не подтверждено: не соглашайтесь на платный план |
| Сон/приостановка/срок жизни проекта | Проверьте актуальный scale-to-zero, compute-бюджет и retention | Проверьте актуальную паузу неактивного проекта и восстановление |
| Соединения | Нужны минимум 5 доступных сессий при WORKERS=2; transaction pooler не подходит | То же; direct endpoint может требовать IPv6, проверяйте доступность из Render |
| Доступ из вашего Render | Не проверен без хоста и учётных данных | Не проверен без хоста и учётных данных |

Это сравнение требований совместимости, а не подтверждённая оферта бесплатных ресурсов. Основной код работает с обоими стандартными PostgreSQL-провайдерами; создание аккаунта и базы требует пользователя. Render Free Postgres не выбран как постоянная база: его срок жизни и ограничения нужно проверять отдельно, и его нельзя считать бессрочным.

## Render и внешние инструменты

Официальные страницы:

- https://render.com/docs/free
- https://render.com/docs/web-services
- https://open-meteo.com/en/pricing
- https://open-meteo.com/en/terms
- https://docs.tavily.com/documentation/api-credits

Сон Render через 15 минут, эфемерная файловая система и холодный старт учтены как исходные условия задачи. Текущие бесплатные часы, build minutes, CPU/RAM, исходящий трафик и порядок паузы здесь независимо не подтверждены. Непрерывный трафик 6000 запросов в день может не оставлять времени для сна; нужно считать часы, а не обещать бесплатный SLA. Тест Docker с 512 MiB — техническая проверка выбранного лимита, не подтверждение тарифа Render.

Open-Meteo и Tavily вызываются только по смысловому запросу модели. У Open-Meteo проверьте текущие бесплатные некоммерческие лимиты, правила коммерческого применения и атрибуцию. У Tavily проверьте бесплатные credits, число credits для basic search и отсутствие платного автосписания. Без ключа Tavily поиск явно отключён. Автоматических покупок/upgrade нет; бот не может запретить списания, если пользователь сам подключит оплачиваемый аккаунт.

Для продолжения проверки документации в облачной среде нужны сетевые разрешения для указанных официальных хостов; для запуска — `api.telegram.org`, `api.groq.com`, внешний PostgreSQL-хост и при необходимости `api.tavily.com`, `geocoding-api.open-meteo.com`, `api.open-meteo.com`. PostgreSQL использует TCP/TLS, не HTTPS-прокси: в ограниченной облачной среде нужен поддержанный TCP-доступ. На обычном Render проверяйте его реальную исходящую сеть.
