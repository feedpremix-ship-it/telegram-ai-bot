# Аудит приложенного bot.py

За основу анализа взят приложенный файл размером 17370 байт, а не более старая версия 7207 байт в репозитории. Исполняемые инструкции из исходного кода не выполнялись. Конфигурация действующего Render и секреты не читались/не менялись.

| Проблема | Что обнаружено | Что изменено |
|---|---|---|
| Модели | В default есть `deepseek-r1-distill-llama-70b`; текущий каталог недоступен | Настраиваемые кандидаты gpt-oss; `/models`-проверка при старте; последовательный fallback при подтверждённом отсутствии |
| Поиск | Есть заявления о поиске, но нет функции запросов поисковому API | Настоящий опциональный Tavily basic search; без ключа честно отключён |
| SQLite | Создаётся на локальном диске, данные теряются с эфемерным диском | PostgreSQL обязателен, TLS проверяется, скрипт read-only миграции backup |
| Конкуренция | `concurrent_updates(True)`, load/append истории отдельными операциями | Постоянная очередь, только одно принятое обновление пользователя обрабатывается одновременно, пара реплик сохраняется атомарно |
| Длина Telegram | Один `reply_text` независимо от длины | Разбиение с учётом UTF-16 до HTML; каждый фрагмент отдельный корректный HTML |
| Разметка | Regex только для `*`/`**`, блоки кода не поддержаны | Экранирование произвольного HTML, ограниченный Markdown, inline code и fenced pre, списки как обычный текст |
| Webhook | Нет секрета; 200 до постоянного сохранения | Секрет сравнивается constant-time; 200 после INSERT; размер body ограничен; 503 при сбое БД/переполнении |
| Диалоги | Нет меню/очистки/нового диалога | Кнопки, команды, memory toggle, auto/short/long, /new и /clear удаляют текущий контекст |
| Статистика | `bump_quota` только после успеха, fire-and-forget | Постоянный журнал каждой API-попытки до отправки, состояние ошибки, actual tokens при наличии, консервативные резервы, неопределённые попытки |
| Расход квот | Stagger запускает резерв одновременно, cancel не отменяет списание | Нет гонки моделей; 429/timeout/5xx не вызывают автоматическое дублирование; Retry-After и локальные бюджеты |
| Погода/перевод | Широкие keyword regex, city split по словам, перевод удаляет совпадения | Модель выбирает функцию по смыслу, полный city параметр, явные команды, перевод получает исходный текст |
| 700 символов | Искусственный предел в системном prompt | Длина по сложности и пользовательской настройке, токенный потолок отдельный |
| URL | Единого запрета нет | Единая постобработка текста для всех режимов; явная просьба разрешает URL; автоматической проверки доступности URL нет |
| Безопасность | Сырые исключения и фрагменты ответов API выводятся в чат | Безопасные сообщения, без токенов/URI/body API в логах; /stats только ADMIN_USER_IDS; callback и личный чат авторизуются |
| Графики | Отсутствуют | Ограниченный математический AST, отдельный процесс с тайм-аутом, PNG в памяти; без eval/exec |

Переразбиение на модули обосновано: старый файл связывает SQLite, сеть, UI и конкурентную обработку. Замена постоянного хранилища и webhook-очереди затрагивает жизненный цикл приложения; точечный regex-патч не решает эти дефекты. Сохранены основной Telegram/Groq стек, имена существующих TELEGRAM_TOKEN/GROQ_API_KEYS/WEBHOOK_URL/PORT/ALLOWED_USER_IDS и принцип простого личного чата.

Что не заявлено: архив нескольких именованных диалогов, долгосрочная семантическая память отдельно от контекста, нейросетевая генерация картинок, прогноз на будущие дни, exactly-once доставка, подтверждённые текущие бесплатные тарифы и 6000 запросов/сутки. Полный источник Groq/Render не был доступен для live проверки. Действующий деплой и перенос настоящей базы не выполнялись.

Финальная проверка: обновлены и зафиксированы runtime/test зависимости; pip-audit не нашёл известных уязвимостей. Исправлены закрытие pool при потерянной сессии leader, health при потере singleton-lock и сериализация token reserve на границе UTC-дня. На таблицах включён PostgreSQL RLS без публичных политик (доступ владельцу/direct DB). Добавлены read-only scripts/check_database.py и DEPLOYMENT.md с планом отката. Реальные доступы Render и PostgreSQL не появились; это остаётся внешним блокером.
