# Проверки этой версии

Проверено в облачной Linux-среде на Python 3.11.17, 4 ноября 2026 года. Production-сервисы не изменялись.

## Автоматические проверки

Команда (с временной локальной PostgreSQL 16 в Docker):

```bash
TEST_DATABASE_URL=postgresql://postgres@127.0.0.1:15432/postgres \
PYTHONDONTWRITEBYTECODE=1 MPLCONFIGDIR=/tmp/mpl-bot \
/workspace/venvs/telegram-ai-bot/bin/python -m pytest -q
```

**Результат финального прогона: 68 passed, 0 failed, 0 skipped; 14 предупреждений зависимостей, 7,29 с.** Путь Python относится только к этой облачной среде; команды для Windows приведены в README.

Покрытие:

| Требование | Фактически проверено |
|---|---|
| Импорт/запуск | Импорт модулей, сборка Telegram Application, полный async lifecycle с реальной БД и подменой API |
| Конфигурация | Обязательные значения, TLS URL, webhook URL/secret, числовые границы, выбор первого существующего ключа |
| Обычный диалог | Groq mock response → форматированный Telegram reply → сохранение пары реплик |
| Память/очистка | PostgreSQL сохранение/чтение, выключение, очистка контекста и последнего запроса |
| Конкуренция | Два настоящих worker, один пользователь последовательно, разные пользователи параллельно |
| Изоляция | Два user ID, запрет групп, callback-настройки и admin-only stats |
| URL | Запрет по умолчанию, явная просьба, https/www/t.me/другие TLD/tg-схемы |
| Форматирование | HTML escaping, bold, inline/pre code, списки, длинные ответы и UTF-16 emoji |
| Ошибки Groq | 401/403/429/500, timeout, пустой ответ, удалённая модель, отсутствие параллельного fallback |
| Лимиты/повторы | Атомарный дневной/минутный бюджет, Retry-After, cooldown, spam pause, ручной retry, повтор доставки без нового LLM |
| Webhook | Реальный локальный HTTP, проверка секрета, неверный JSON, health 503/200, queue capacity, запись в PostgreSQL до 200, дедупликация |
| Графики | PNG функции/bar, отказ опасным AST-выражениям, отдельный процесс, неверные данные pie |
| Погода/перевод/поиск | Подменённые Groq/Open-Meteo/Tavily ответы, полное имя города, неоднозначность, перевод слова «погода» без keyword-маршрутизации |
| Перезапуск | Закрытие pool и открытие заново: история сохранена, pending-задания доступны, processing помечены interrupted |
| Сбой БД | Worker повторяет запись конечного состояния после временной ошибки, не повторяет вызов модели |
| SQLite migration | Настоящий SQLite-файл → PostgreSQL, read-only источник, повтор без дублей, rollback при конфликте |
| Синтетическая нагрузка | 6000 MockTransport LLM-вызовов, проверено не более 2 одновременных; реальная сеть и квоты не используются |

Синтетический тест не доказывает производительность Render, бесплатность 6000 реальных запросов или семантическое качество модели. Тест перевода с заглушкой проверяет сохранение текста и маршрут, а не переводческие способности живой модели.

## Docker и ресурсы

Образ собран по Dockerfile на `python:3.11-slim`; зависимости установлены с проверкой TLS, session CA передан через необязательный BuildKit secret и не попал в слои образа.

В контейнере с `--memory=512m --cpus=1` выполнены импорт `bot`, создание настоящего PNG `sin(x)` через matplotlib. Первый измеренный результат: PNG 42392 байта, peak RSS основного процесса 97808 KiB (около 96 MiB). Это единичный тест функции построения, не пиковое потребление всего сервиса при нагрузке. В модели приложения одновременно не более одного chart subprocess; суммарную память production необходимо наблюдать в Render.

Дополнительно выполнены `uv pip check`, `compileall`, `git diff --check`. У pytest есть предупреждения об устаревающих вызовах pyparsing внутри matplotlib; они не отключены и не скрыты.

## Что не выполнено

- Реальные запросы Telegram/Groq/Tavily/Open-Meteo: отсутствуют production-ключи и необходимые сетевые разрешения.
- Текущий каталог/поддержка параметров Groq, сравнение русского качества моделей и актуальные квоты аккаунта: не проверены живым API.
- Подтверждение сегодняшних тарифов, карты, free storage/compute/egress и лимитов соединений Neon/Supabase: официальные сайты заблокированы исходящим прокси этой среды.
- Настоящий Render deploy, его холодный старт, часы, длительная нагрузка, сообщения с Android/iOS/Desktop: доступа к действующему сервису нет.
- Перенос настоящей пользовательской базы: backup не предоставлен. Использован созданный тестовый SQLite-файл.
- GitHub push не выполнялся, платные подписки не создавались.

Проект подготовлен к интеграционной проверке после настройки внешних подключений; полностью проверенным production-развёртыванием он не объявляется.

## Финальный аудит

Повторный pip-audit 2.10.1 установленного Python-окружения: **No known vulnerabilities found**. Обновлены python-telegram-bot 22.8, aiohttp 3.14.5, httpx 0.28.1, asyncpg 0.32.0, python-dotenv 1.2.4, pytest 9.0.3 и pytest-asyncio 1.3.0. Все транзитивные runtime-зависимости зафиксированы в requirements.txt. Отсутствие известных уязвимостей не доказывает отсутствие неизвестных дефектов. Добавлены RLS без публичных политик, безопасное закрытие pool при потере leader-соединения и health 503 при потере singleton-lock. План выкладки и отката: DEPLOYMENT.md.
